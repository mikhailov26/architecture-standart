## Функциональные требования (Use Cases)

| № | Действующие лица или системы | Use Case | Описание шага |
|:-:|---|---|---|
| 1 | БО депозиты/кредиты → Сервис ставок | Публикация версии ставок | Загрузка из XLS, валидация, утверждение и публикация версии; ведение истории. |
| 2 | КЦ (внутренний) → Витрина/API ставок | Просмотр текущих/будущих ставок | Оператор видит актуальные ставки (и `effective_from`) в интерфейсе КЦ. |
| 3 | Банк → Партнёрский КЦ (внеш.) | Передача файла со ставками | Формирование CSV/JSON, шифрование (PGP/SMIME), отправка по защищённой почте; контроль доставки. |
| 4 | БО депозиты → Сервис ставок | Внеплановое обновление | Экстренная публикация новой версии ставок с триггером мгновенной рассылки партнёру. |
| 5 | Операционный контроль → Сервис ставок/Почтовый шлюз | Аудит и мониторинг | Просмотр истории изменений, журнал рассылок, статусы успешной/неуспешной доставки, ретраи. |

## Нефункциональные и архитектурно-значимые требования (выдержка)

- **Доступность/надёжность:** обновлённые ставки доступны в КЦ ≤ 5 минут после публикации; RPO ≤ 15 мин / RTO ≤ 60 мин для контура ставок.
- **Производительность:** чтения ставок из КЦ ≤ 300 мс; формирование файла для партнёра ≤ 30 с при целевой номенклатуре.
- **Интеграционные ограничения:** у партнёра **нет API/SFTP** — допускается только получение **входящих файлов по защищённой почте**.
- **Безопасность:** TLS 1.2+ внутри банка; шифрование файлов PGP/SMIME, цифровая подпись (`.sig`) и контроль целостности (`.sha256`); RBAC и аудит операций.
- **Технологии:** БД MS SQL/Oracle; предпочтительно Java/Spring Boot или .NET для новых сервисов; совместимость с будущей Kafka на уровне интерфейсов.
- **Операционные требования:** мониторинг/алерты по публикациям и доставке; ретраи, DLQ; регламенты ротации ключей PGP/SMIME.

## Решение (диаграммы C4)

Диаграммы находятся в `Task4`:
- **Context.puml** — диаграмма контекста (L1).
- **Components.puml** — диаграмма компонентов (L2) для нового кейса.

### Краткое описание решения

1. **Сервис ставок (Rates)** централизует публикацию версий ставок (из XLS на MVP), хранение версий (с `effective_from/effective_to`), аудит; предоставляет проекцию `rates_view_current` и/или API `GET /rates` для чтения.
2. **Интеграция внутреннего КЦ**: read‑only доступ к `rates_view_current` (через DB‑view/FDW/materialized view) или тонкий REST‑клиент; кэш и инвалидация по событию публикации.
3. **Экспортёр файлов партнёру** генерирует CSV/JSON, шифрует и подписывает, отправляет через почтовый шлюз; хранит статусы доставки и выполняет ретраи.
4. **Почтовый шлюз** обеспечивает защищённую отправку, квитанции, мониторинг; ключи PGP/SMIME хранятся и ротируются согласно регламенту.
5. **Партнёрский КЦ** получает письма и импортирует файл в свою систему (ручной/авто‑импорт на стороне партнёра).

## Альтернативы

1. **SFTP/FTPS** или **B2B API** — отклонено: отсутствует возможность у партнёра в MVP.
2. **Общий объектный стор с пресайнд‑ссылками** — требует внешнего HTTPS‑доступа/авторизации партнёра, которого нет.
3. **Ведение ставок только в АБС** — стратегически возможно, но увеличивает срок MVP; оставлено как целевое решение горизонта 12 месяцев.

---

## Недостатки, ограничения, риски

- Зависимость от корректности XLS; требуется строгая валидация и правила публикации.
- Почтовая доставка имеет менее детерминированные SLA; необходим мониторинг и ретраи.
- Временная дубликация источника (если АБС параллельно ведёт ставки) — нужен единый источник истины и регламент.
- Операционные риски: управление ключами, списками получателей, инцидент‑менеджмент.

## Крупные задачи (по системам)

**Бэк‑офис депозиты/кредиты**
- Шаблон XLS v1 (валидации, форматы).
- Регламент «черновик → утверждение → публикация».

**Сервис ставок (Rates)**
- Модель данных (версии, продукты, сроки, диапазоны), аудит.
- Импорт XLS + отчёт об ошибках.
- Публикация/проекция `rates_view_current`, API `GET /rates`.
- Вебхук `rates.published`; RBAC; метрики/алерты.

**Система КЦ (внутр.)**
- Интеграция (DB‑view/REST‑адаптер).
- Экран ставок, фильтры/поиск; кэш и инвалидация.
- Нагрузочное тестирование чтений.

**Экспортёр файлов партнёру + Почтовый шлюз**
- Генерация CSV/JSON; подпись (`.sig`) и хэш (`.sha256`).
- Шифрование (PGP/SMIME), хранилище ключей, ротация.
- Настройка рассылки, ретраи, мониторинг, журнал доставки.

**ИБ‑безопасность/Операции**
- Учётная запись рассылки, лимиты/квоты.
- Дашборды, алерты, runbooks (нет доставки/битый файл).
